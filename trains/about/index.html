Building the Chicago ’L’ Tracker

An 8-bit map of every CTA train, built to be the thing you leave open while you put your shoes on. Here is what it does, the calls I made, and what shipping it taught me.

Why a map

The CTA’s own tools answer “when is my train?” as a list. That’s the right answer on a platform, but it hides the system: where the gaps are, whether the Red Line is bunched up, how the Loop is doing. A map shows all of that at a glance. I wanted one that felt like Chicago and was fun enough to keep open, so it looks like an old video game.

What it does

  • Every train on all eight lines is a small two-car sprite in its line’s color, pointed the way it’s moving, with a headlight and a fading trail. Click one for its run number, destination and next stop.
  • Next trains: pick a line and station, or click a station, for a live countdown in each direction. Click an arrival to jump to that train.
  • Your stops: save stations and the page opens straight to the first one. Favorites stay in your browser.
  • Day, dusk and night follow the real sun over Chicago. At night the mile streets light up like streetlights.
  • Landmarks: about 35 places most Chicagoans would know, from the Bahá’í Temple and Northwestern to Superdawg, the Little Village Arch and the Museum of Science and Industry.
  • Things to find: a lake monster, the Navy Pier wheel, a green river in March and holiday trains in December.

Decisions worth explaining

Real geography, drawn one pixel at a time

Track shapes, stations and the lakefront come from the City of Chicago’s open data. A small script turns them into a 40 KB file the page loads once. The map is drawn on a low-resolution canvas with a line algorithm that places whole pixels, so nothing is ever blurred. Where lines share track, as in the Loop, they run side by side in separate lanes, the way a transit diagram draws them.

A believable sample run before the data arrives

The CTA’s live feed needs an API key, and I didn’t want to wait for one to start. So the map runs a simulation: trains follow real routes, pause at real stops and turn at the terminals. Positions come from the clock, so everyone sees the same trains at the same moment. The arrivals board reads the same timetables, which keeps the countdown and the dots in agreement. The page labels all of it as a sample run.

Live data without exposing a key

The feed can’t be called from a browser without leaking the key, so a small Cloudflare Worker sits in between. It holds the key, caches each response for 20 seconds so every visitor shares one upstream call, and serves both train positions and station arrivals. The page switches to live data with a one-line change and falls back to the sample run if the feed drops.

Making pixel type actually crisp

The first font looked soft. Measuring its outlines showed why: it isn’t drawn on a strict grid, so its edges land between screen pixels. Jersey 10 sits on an exact 75-unit grid, and at 18⅔ pixels one font pixel is exactly one screen pixel. The fix was arithmetic, not taste.

Detail without clutter

My first pass put a note beside nearly every station. It was too much, and most of it wasn’t anything a local would point to. The second pass kept only places people in each part of the city would recognize, and spread them out on purpose so downtown doesn’t swallow the map. Downtown landmarks wait until you zoom in, and when two icons would overlap, the less important one waits for a closer zoom.

How it shipped

I built it with Claude Code, directing the product and design calls and reviewing each change. Every release went out as a small pull request with automated tests and a check in a real browser at desktop and phone sizes, and the larger ones got an independent code review first. That review earned its keep: it caught an arrivals list that rebuilt itself every second and swallowed clicks, and trains listed two or three times because stations a block from the track were matched as stops.

The most useful lesson came after launch. A release went live and nothing changed for visitors. Cloudflare told browsers to keep scripts for four hours but the page for only ten minutes, so people got the new page running the old code. Every file the tracker loads now carries a version number, and a release changes one number in one file.

What’s next

  • Switch on the live CTA feed for positions and arrivals.
  • Service alerts and elevator outages on the map.
  • Links that open to a station or train, for sending to a friend.
  • An installable phone version that opens to your stops.
